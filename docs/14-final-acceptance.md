# 最终单次验收定义

更新：2026-11-03。用户明确将“注入一次通过的乐跑次数”作为最终目标。
本项目将其验证为：**独立MuMu中经原App正常流程保存的一条可查询有效记录，
对应有效次数从实测基线N增加到N+1**。这是目标，当前尚未达到。

## 不可替代的验收证据

1. 正常原App/正确账号与规则来源已现场核实。账号原值只留本机，不公开。
2. 开始前读取当前有效次数N、已有未完成记录及其状态；若存在旧记录先保留并核对，不默弃、不新开覆盖。
3. 本人验证由用户完成；正式开始前确认用户可以立即接手，不能因架构师授权而代做/伪造。
4. 原App实际显示的打卡、里程、配速/时段等条件满足后，才允许走正常结束/保存流程。
5. 有新的原App记录详情和记录标识（本机私有），并显示有效/通过；待审核不算通过。
6. 历史列表、详情和有效次数N+1一致，正常重新进入后再次读取，排除仅本地缓存/页面显示。
7. 当前App认可与后续服务端复核分开记录；没有后续证据不能声称永久审核通过。

不以Mock accepted=1、直接改计数、本地回包、未知接口响应、里程数字或历史成功个例冒充本次通过。
不直接调用未确认的成绩写接口，不复制登录资料，不采集/重放生物材料。
