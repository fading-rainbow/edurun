# 独立 MuMu 对照

此对照由用户批准安装；不是替换原AVD，也不是已通过正式乐跑验收。

## 实测状态

- 官方网易签名完整组件：产品6.8.4.0、管理器1.8.4.5733、Android12引擎12.8.4.5734。
- 新建独立实例 `BudaoRun_MuMu`；没有克隆、导入或读取旧环境登录数据。
- 首次启动约26秒；4核/3GB；实际Android release12、SDK32、ADB shell uid2000。
- 官方root开关false，Hyper-V仍开启。未关闭主机安全/虚拟化设置，没有重启电脑。
- 原始乐跑4.3.0/code230的ARM64包通过协议/引导后进入MainActivity。
- 未登录账号的静止自由预检进入MapRunActivity，计时推进，里程0.00km；显示GPS信号弱。
  长按暂停后停止该测试App，没有点击结束/上传，也没有正式打卡或有效记录。
- 随后独立匿名GPS短程测试约35秒、3m/s：按单调时钟发送约102.17m的旧KML片段，
  App里程从0.00变为0.10km，GPS从弱变优。前台/模式检查及2秒时钟间断阈值持续生效；
  暂停后停止目标App，没有点击结束/上传。没有自然运动波形，不能判定正式有效。
  GPS文字采样曾为“优”，但随后截图又为“弱”；信号仍波动，不能宣称持续优或稳定修复。
- 只读诊断实际出现用于定位的GNSS卫星（多次回调4–11个），与API34恒为0不同。
  该差异不是目标App里程/有效性证明。
- 加速度约25Hz、陀螺仪约200Hz；没有标准StepCounter/StepDetector。
  官方 `gyro` 命令是重力方向控制，不等同于任意陀螺仪样本输入；`shake` 实测引起大幅
  加速度变化，但不是自然跑步波形，不能把它宣称为真实步伐或HAR重放。
- 输入原KML数字时，实际GPS误差约1.27km；用现成开源
  [eviltransform](https://github.com/googollee/eviltransform) 0.1.1进行WGS84→BD09转换后，
  三个独立静止锚点的实际GPS误差约1.96/2.42/2.14m。
  这是当前版本的输入坐标实测，不证明原KML道路/学校区域已标定，也不修改来源标志。
- 原API34保留的QQ授权已通过；新MuMu的QQ9.3.70尚未认证。
  手机及真实大屏几何对照均未观察到扫码登录入口；没有请求睡眠期间的短信或读取密码。
- 官方包附带的 `MuMuRemoteService` 已通过标准Windows服务控制停止并禁用；其监听已消失，
  项目实例仍正常运行。没有连接远程控制账号或改变其他用户服务。

## 只读入口

```powershell
uv run budao inspect-mumu --receipt .local/setup/mumu-owned-instance.json
```

该入口不启动乐跑，不点击界面，不移动，不发送模型请求，不提交记录。
只读本项目debug诊断App；不读取QQ/乐跑的私有数据目录。诊断App需已运行，
超过10秒、时钟在未来或属于前一次启动的快照拒绝作为当前证据。

`.local/setup/mumu-owned-instance.json` 是现场创建凭据，不能提交到Git。
适配器验证固定的已签名管理器SHA256、独立安装/实例目录、实例名、创建时间、
未导入状态、实时管理器信息、root关闭、实际uid/SDK及本机ADB端口。
设备离线、端口/身份变化、管理器更新或导入旧数据均拒绝操作。
原 `AndroidBridge` 的QEMU/AVD白名单没有放宽；MuMu不能用于QEMU控制台或全局ADB操作。

## 后续关卡与回退

仍需新环境正常认证、GPS业务里程接受、学校区域/道路标定、逐点出现/确认、
自然运动数据通道及正式有效记录证据。不得以本页结果替代这些关卡。

只停止本项目实例时，先用现场凭据验证身份，再对该索引调用官方
`MuMuManager control --vmindex <owned-index> shutdown`；不要使用 `all`。
原API34数据保留，可停止新对照后回到原启动入口。不卸载、不删除实例或wipe-data。
若用户日后确需远程功能，可单独恢复新装服务；本项目不自动恢复或启用远程访问。
